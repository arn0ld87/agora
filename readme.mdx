## Warum Agora existiert

Viele Texte werden erst dann wirklich getestet, wenn sie bereits draussen sind:
Pressetexte, Policy-Entwuerfe, Produktkommunikation, Whitepaper, Dossiers.
Agora verschiebt diese Auseinandersetzung in eine lokale, reproduzierbare
Simulationsumgebung.

Das Ziel ist nicht ein allwissendes Urteil. Das Ziel ist ein belastbares
Arbeitsbild:

- Welche Stakeholder-Cluster reagieren aehnlich?
- Welche Aussagen erzeugen Reibung?
- Welche Begriffe kippen die Tonalitaet?
- Welche Argumente werden aufgegriffen, umgebaut oder ignoriert?
- Welche Evidenz stuetzt den Report wirklich?

## Architektur

```text
frontend/
  Vue 3 + Pinia + Zod + Vite
  Wizard, Runs Dashboard, Graph UI, Compare UI, Report UI

backend/
  Flask + Pydantic v2 + uv
  contracts/       API Single Source of Truth
  api/             Auth, Graph, Simulation, Report, Runs, Status
  services/        Graph Build, Persona Review, OASIS Runner, ReportAgent
  storage/         Neo4j, Embeddings, NER, Search
  scripts/         OASIS-Subprozess-Runner

runtime
  Neo4j 5.18+      Knowledge Graph
  Redis            Pub/Sub-IPC
  Ollama/API       LLM + Embeddings
  OASIS/CAMEL      Multi-Agent-Simulation
```

## Security-Modell

Agora v1 ist bewusst Single-User-only.

- Shared `AGORA_AUTH_TOKEN` fuer `/api/*`.
- Signed Tickets fuer URL-bound SSE/Downloads.
- `?token=` ist im Non-Debug-Modus blockiert.
- Rate-Limits auf den teuren und sensiblen Trigger-Pfaden.
- Reverse-Proxy-Header werden nur via explizitem `ProxyFix`-Trust ausgewertet.
- Kein Multi-User-AuthN/AuthZ-Stack in v1.

Das ist fuer localhost, Lab-Setups und Tailnet gedacht. Nicht direkt ins
oeffentliche Internet stellen.

## Quickstart

```bash
git clone https://github.com/arn0ld87/agora.git
cd agora
cp .env.example .env

ollama pull qwen2.5:32b
ollama pull qwen3-embedding:4b

docker compose up -d --build
```

Danach:

- Frontend: http://localhost:5173
- Backend Health: http://localhost:5001/health
- Neo4j Browser: http://localhost:7474

Lokale Entwicklung:

```bash
npm run setup:all
npm run dev
npm run check
```

## Modell- und Embedding-Hinweise

Der aktiv gepflegte Pfad ist:

```env
LLM_MODEL_NAME=qwen2.5:32b
EMBEDDING_MODEL=qwen3-embedding:4b
VECTOR_DIM=2560
```

Wenn das Embedding-Modell gewechselt wird, muss `VECTOR_DIM` passen. Bei
Dimension-Drift muessen Neo4j-Vector-Indexes neu aufgebaut werden.

| Modell | VECTOR_DIM |
|---|---:|
| `nomic-embed-text` | 768 |
| `embeddinggemma:300m` | 768 |
| `qwen3-embedding:4b` | 2560 |
| `qwen3-embedding:8b` | 4096 |

## Fuer Entwickler

```bash
cd backend && uv run pytest
cd backend && uv run ruff check app/ tests/
cd backend && uv run python -m app.contracts.dump_schemas

cd frontend && npm run check
```

Design-Grundsaetze:

- Tests sind die Spec.
- Pydantic v2 ist die Quelle fuer API-Vertraege.
- Zod-Spiegel im Frontend bleiben synchron.
- Keine Secrets in Logs, Diffs, Artefakten oder Beispielen.
- Neue Runtime-Defaults muessen in `docu/STATUS.md` oder der passenden Doku sichtbar werden.
