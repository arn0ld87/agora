## Ausgangslage

`scripts/sync-status.sh` existierte bereits mit vollständig implementiertem `--check`-Modus (marker-delimited autogen-Sections in `docu/STATUS.md`). Die Funktion fehlte jedoch als CI-Gate in `.github/workflows/ci.yml`.

## Befund

```
$ bash scripts/sync-status.sh --check
DRIFT: docu/STATUS.md weicht von autogenerated Inhalt ab
22c22
< | Backend Tests (collected) | 2000 | ...
---
> | Backend Tests (collected) | 2013 | ...
EXIT: 1
```

STATUS.md war manuell auf 2000 Tests gepflegt, aktueller Wert via `pytest --collect-only` ist 2013. Genau der beschriebene Drift-Fall.

## Maßnahmen

### 1. STATUS.md regeneriert

```bash
bash scripts/sync-status.sh      # aktualisiert VERSIONS + TESTS Marker-Blöcke
bash scripts/sync-status.sh --check  # → EXIT 0, OK
```

### 2. CI-Job ergänzt (`.github/workflows/ci.yml`)

Neuer Job `status-sync` am Ende der Workflow-Datei:

```yaml
status-sync:
  name: STATUS.md drift check (MAI-16)
  runs-on: ubuntu-latest
  steps:
    - name: STATUS.md drift check (MAI-16)
      run: |
        bash scripts/sync-status.sh --check
```

Der Job installiert Python 3.11, uv und synct Backend-Dependencies (für `pytest --collect-only`), dann ruft er `sync-status.sh --check` auf. Exit 1 bei Drift bricht CI ab.
