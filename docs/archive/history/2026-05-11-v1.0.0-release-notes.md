## Highlights

- **Output-Vertrag erzwungen.** Kein Report verlässt die Pipeline ohne die 11 Pflichtabschnitte
  oder mit weniger als 50 Personas. Validator + JSON-Schema-Drift-Gate auf CI-Ebene.
- **Evidence-Härtung.** Claims außerhalb `confidence_label="low"` brauchen mindestens einen
  Evidence-Anker. Evidence-lose Claims wandern automatisch in `hypotheses[]` oder
  `data_gaps[]`. Low-Confidence-Marker im exportierten Markdown.
- **ReportV3-Persistenz + Markdown-Renderer.** Strukturierte Aggregation (Personas, Segmente,
  FrictionPoints, TrustSignals) aus `artifact_store`, deterministisches Markdown mit
  `simulated_quote`-Blockzitaten und Mode-Banner im Header.
- **Drei Vertrauensmodi.** `strict` (nur belegte Claims, harter Anchor-Validator),
  `balanced` (Default — belegte Claims + markierte Hypothesen),
  `explorative` (alles durch, EXPLORATIVE-Modus). Frontend-Selektor mit localStorage-Persistenz,
  i18n in `de.json`/`en.json`, Backend-Übergabe via `?mode=`-Query-Param.
- **Export-Vollständigkeit.** Markdown, JSON, CSV (Personas/Segmente/Claims, RFC-4180),
  ZIP-Bundle (serverseitig via Python-stdlib, kein jszip), Browser-Print-PDF.
- **Live-Settings.** `GET`/`PUT /api/settings` mit Pydantic-Validierung, Secret-Redaction,
  `settings.changed`-Event-Bus. Services lesen via `settings_layer.get_*()` — Live-Übernahme
  ohne Container-Restart für `AGORA_PARALLEL_PERSONA_COUNT`, `AGORA_PERSONA_DETAIL_LEVEL`,
  `ONTOLOGY_MAX_TOKENS`. Issue [#212](https://github.com/arn0ld87/agora/issues/212) geschlossen.
- **CI-Hardening.** `step-security/harden-runner` (audit-mode) in 9 Workflows,
  `aquasecurity/trivy-action` für Container-CVE-Scans, `ossf/scorecard-action` für
  Supply-Chain-Score. Issues [#351](https://github.com/arn0ld87/agora/issues/351),
  [#352](https://github.com/arn0ld87/agora/issues/352),
  [#353](https://github.com/arn0ld87/agora/issues/353) geschlossen.

## Phasen-Detail

### Phase 1 — Output-Vertrag absichern

- **P1.1 Pflichtabschnitt-Validator** — `contract_validator.py`,
  `ReportOutlineModel.require_default_sections`. Reports ohne 11 Pflichtabschnitte werden
  als `INCOMPLETE` markiert, `missing_sections[]` strukturiert im API-Response.
- **P1.2 Persona-Mindestanzahl** — `MIN_PERSONA_TABLE_ROWS = 50` als harter Floor in
  `prepare_service.py`. Frontend-Slider ist auf `min=50` gepinnt.
- **P1.3 Schema-Drift-Gate** — `app.contracts.dump_schemas` ist als CI-Job verdrahtet;
  Drift zwischen Pydantic-DTOs, `schemas/*.json` und Frontend-Zod-Schemas blockt CI.

### Phase 2 — Evidence-Härtung

- **P2.1 Evidence-Anker-Pflicht** — `ReportClaimModel.non_low_claims_need_evidence` +
  `_finalize_section_claims` Data-Gap-Routing + `migrate_legacy_claims_to_anchored` für
  Bestandsreports.
- **P2.2 Low-Confidence-Marker** — `render_claim_to_markdown` rendert `⚠️ Low-Confidence-Hinweis`
  als Blockzitat im Markdown-Export.
- **P2.3 Hypotheses-Slot** — separater Worktree `feat/m11-7c-report-hypotheses` (außerhalb
  der v1.0-DoD-Liste, läuft als eigenständiger Slice weiter).

### Phase 3 — Report-Qualität

- **P3.1 ReportV3-Persistenz** — `migrate_v2_to_v3` + `write_report_v3`/`read_report_v3`.
  Plus Followup mit echter Persona/Segment/FrictionPoint/TrustSignal-Aggregation aus
  `artifact_store.read_json(sim_id, "reddit_profiles")`.
- **P3.2 Markdown-Renderer** — `render_report_v3()` vollständig, Backend-Endpoint
  `export_report?format=md` bevorzugt `report-v3.md` mit v2-Fallback.
- **P3.3 Quote-Source-Marker** — `simulated_quote`-Tags als markierte Blockzitate gerendert.
- **P3.4 PDF-Print-Doku** — Browser-Print als kanonischer PDF-Pfad dokumentiert.

### Phase 4 — Vertrauensmodi + Export

- **P4.1 Report-Modi** — `ReportMode = Literal["strict","balanced","explorative"]` in
  `report_v3.py`, `_resolve_report_mode` in `api/report.py`, Manager/Workflow propagieren
  Mode, Mode-Banner im Markdown-Renderer, Frontend-Komponente `ReportModeControls.vue`
  (eigene Komponente — getrennt von `ReportModelControls.vue` für LLM-Auswahl) mit
  localStorage-Persistenz unter `agora.reportMode`.
- **P4.2 CSV-Export** — `GET /api/report/<id>/export?format=csv&table=personas|segments|claims`
  (RFC-4180), `csv_export.py` als pure-Function-Helper.
- **P4.3 ZIP-Bundle** — `?format=zip` baut serverseitig on-the-fly aus
  `report-v3.md`/`report-v3.json`/`evidence-map.json` + 3 CSVs (Python-stdlib `zipfile`).
- **P4.4 E2E-Smokes Modi** — drei Playwright-Smokes über strict/balanced/explorative inkl.
  Banner-Prefix-Check und `report_mode`-JSON-Feld-Check. Plus Default-Test ohne Mode-Param.

## Migrations-Hinweise

- **Bestandsreports** (schema_version=2) werden beim Reload automatisch durch
  `migrate_legacy_claims_to_anchored` + `migrate_v2_to_v3` aufgehoben. Kein manueller
  Migrations-Schritt nötig. Wenn das `artifact_store`-Argument an `migrate_v2_to_v3` fehlt,
  bleibt die DataGap-Fallback-Logik aktiv — Bestandsreports verlieren keine Daten.
- **Settings-Keys**: `AGORA_PARALLEL_PERSONA_COUNT`, `AGORA_PERSONA_DETAIL_LEVEL`,
  `ONTOLOGY_MAX_TOKENS` werden ab v1.0 aus `settings_layer` gelesen. Bestehende
  `.env`-Werte bleiben kompatibel — werden beim ersten Lauf in `var/runtime-settings.json`
  übernommen. Live-Override via `PUT /api/settings` greift sofort.
